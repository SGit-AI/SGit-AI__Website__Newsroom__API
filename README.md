# SGit-AI__Website__Newsroom__API

A client-side API: the components, formats and contracts the browser runs on
[newsroom.sgit.ai](https://newsroom.sgit.ai), with no server and nothing to deploy but files.
Published at **api.newsroom.sgit.ai** (this repository's GitHub Pages site) as versioned releases,
`https://api.newsroom.sgit.ai/<release>/<path>`, that the newsroom and sgit.ai pin.

It owns SG Meter (the reading meter: balance, pay by depth, rating, personas, top-up, share; v1.4.0 and the
frozen v1.0.0 to v1.3.1), the component base, the reading-list link grammar and its pages' code, subscribe and
the encrypted share, the reader's vault layer and the vault pane, search and ask, the wire reader, the vendored
vault library (`SGraph-AI__App__Send` v0.2.3, never edited here), the passkey lab, and their tests. The `ids.json`
article-number contract and the persona link format are this repository's formats; the data files are the
newsroom's. The content (the articles and everything generated from them, and the pages themselves) stays in
[SGit-AI__Website__Newsroom](https://github.com/SGit-AI/SGit-AI__Website__Newsroom).

## The website

[api.newsroom.sgit.ai](https://api.newsroom.sgit.ai/) is also the site that explains all this, for publishers and editors, for
developers, for evaluators, and for the agents that keep it: the case, the quick start, the reference, how-to guides, the
review with the map as a graph, the proof, the releases, the articles behind it, and `llms.txt`. It is generated by
`site/build.py` from `site/pages/` (markdown or HTML fragments with front matter), `site/data/articles.json`, the map and the
manifests, into `www/`, which is committed and which CI checks; the deploy publishes it at the root beside the releases.

It wears the newsroom's five themes (`site/assets/themes.css` and `themes.js` are the newsroom's own files, unchanged) and is
held to the newsroom's bar by `tests/test_site.mjs`: every token in every theme, no literal colour, 4.5:1 everywhere, one row
from 1280 up. `site/check.py` is its gate before publishing, the newsroom's validate.js for these pages: every reference
resolves, canonical and chrome on every page, the sitemap and the llms files agree with the tree, no key shapes.
`site/data/versions.json` is the line per version that `/versions/` shows; a version without its line does not build.
Articles written here live in `site/content/articles/<slug>.md`, in the newsroom's article format (its
`admin/content/articles/README.md`: front matter, `!shot` figures, anchored sections, a graph in `graphs/<slug>.json`,
figures in `images/`), so one can be imported into the newsroom unchanged; the build renders each at `/articles/<slug>.html`
with its markdown twin and graph, and lists it on `/articles/`, in the feed and in search.
`site/og.py` draws the link-preview card of every page into `site/og/` (committed, not built: a font renders differently from one
machine to the next, and the build must be the same bytes twice).
What the site has, as newsroom.sgit.ai has it: the five themes and the picker, the bar in eight groups with a dropdown each, the
search over its own pages with the API's own component loaded from this host's release (`/search/`, over `search/docs.json`
and `text.json` in the contract's format), a link-preview card per page, the footer with the disclosure and the network line,
`/versions/` and `feed.xml`, `llms.txt` and `llms-full.txt`, a markdown twin of every page, print and reduced-motion rules.

## The layout

- The served files, at the paths they had in the newsroom: `assets/components/`, `assets/vault-pane/`,
  `assets/search/`, `assets/vendor/sg-vault/`, `assets/vendor/qrcode-generator/`, `assets/subscribe.js`, `assets/newsroom-vault.js`, `assets/door.js`,
  `for/`, `wire/`, `passkey/`. `tools/served.json` is the list; `tools/version.json` the repository's `version` (every
  change that lands on `dev` is one, in small increments: v0.2.1, v0.2.2; the deploy tags it), the reader-code `release`
  the consuming sites pin (`releases/<release>/`, cut only when a served file changes), and the date.
- `releases/<release>/`: each release as published, with `manifest.json` (every path, bytes, SHA-256; which files
  differ from the newsroom's bytes and why). Never edited after it is on `dev`. `python3 tools/release.py cut`
  makes one from the tree; `check` recomputes every hash and fails when the tree is not the release it names;
  `site --out DIR` assembles the Pages site. `tools/live_check.py` asks the live host for every hash after a deploy.
- `tests/`: the newsroom's reader tests, moved here. They serve a checkout of the newsroom (`NEWSROOM=<path>`, or
  `.newsroom/`; CI checks out the ref in `tests/newsroom.json`) and route `https://api.newsroom.sgit.ai/v*/`
  to this tree (`tests/harness.mjs`), so the pages are the real pages and the code is the code under test.
  `BROWSER=chromium|webkit|firefox`. `node tests/test_meter.mjs` and so on. `test_styles.mjs` (Node only) holds the served
  stylesheets to the newsroom's rule that no colour is written outside a theme token.
- `map/before/<newsroom release>/`: the newsroom's map of everything a reader runs, and every file's raw hash, at the
  commit before each cut (`v0.12.10` for v0.1.0, `v0.12.50` for v0.2.0). `map/proof/<release>.json`: the move's proof, written by `tools/prove_move.py`.
- `tools/api_map.py`: the map generator, moved from the newsroom; not yet re-pointed at this tree and a
  newsroom checkout (phase 0 maintenance, to run nightly here).
- `briefs/`: the plan. `2026-10-13__the-move-to-api-newsroom-sgit-ai.md` is the brief refreshed at newsroom
  v0.12.10; the original is the article
  [Go slow to go fast](https://newsroom.sgit.ai/articles/explorer-to-villager-newsroom.html).
- `.github/workflows/ci.yml`: every commit: syntax, the manifest, the build twice, the tests in three engines.
  `deploy-pages.yml`: `dev`, the default branch, is the release branch: check, tag, publish, then the live check.

## The move, in one paragraph

Releases v0.1.0 (from the newsroom at v0.12.10) and v0.2.0 (from v0.12.50, the one the newsroom pins at its v0.13.0) are phase 1 of the brief. 74 files left the newsroom, unchanged apart from
three that a host of their own forced to change, each by the lines that took the site root from the script's own
address and now take it from the page (`vault-pane.js`, `search.js`, `ask.js`; recorded file by file in the
manifest). The newsroom loads them from `https://api.newsroom.sgit.ai/v0.2.0/`, pinned in its
`admin/build/api.json`; its gate checks every reference and the frozen meter copies it keeps. The proof that the
live site serves the same bytes is `map/proof/v0.2.0.json` (and `v0.1.0.json` for the first cut). The 18 findings of the review are issues 1 to 18.
Until phase 4 is finished, the served files are frozen: a change is a new release, with a test that fails without
it, and a reason in the pull request.
